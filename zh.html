我们离终身游戏 agent 还有多远？

一个给自己写代码的 agent 在 10 个浏览器游戏上的证据

摘要

一个终身游戏 agent 应当能凭反馈把任何新游戏玩好，并且玩过的游戏越多，学下一个游戏就越快。我们用一个不更新权重的 agent 检验这个目标离现实有多远：它在一个持久工作区里给自己写技能程序、记笔记、记成绩，所有游戏使用完全相同的提示词，没有任何逐游戏的人工设计。

在 10 个浏览器游戏、约 4 700 局实验中，我们发现：agent 能在单个游戏内学会，但前提是把经验写成可执行的代码；不给它任何记忆结构，它会自己发明出单游戏学习所需的结构。然而它学到的东西几乎带不走：跨游戏收益是一个不随经历增长的常数，同类游戏的经验也没有额外好处。逐级加大环境变化后可以看到，经验只在画面不变时有用，仅把画面颜色反转，经验就从有利变为有害。按持续学习的方式连续学一条游戏链时，它既没有越学越快，还会因为共享代码被改写而忘掉学过的游戏。

结论是：单游戏内的自我改进和自组织记忆已经可以实现，但 agent 存下的经验绑定在像素上，缺少一层与画面无关的表示，这是通往终身游戏 agent 的主要缺口。

1引言

人类玩家有一种能力很少被认真测量：玩过足够多的游戏后，拿到一个新游戏，几局之内就能上手，并且这种上手速度会随经历越来越快。我们把具备这种能力的系统称为终身游戏 agent。它至少要做到三件事：

  • 在一个游戏里越玩越好：只依靠游戏给的反馈，而不是人为它写好的规则。
  • 自己组织记忆：决定记什么、怎么记，而不是由人为每个游戏设计数据结构。
  • 把经验带到下一个游戏：学第 N 个游戏的代价随 N 下降，同时不忘记已经学会的游戏。

大模型的出现让这件事第一次可以在不训练权重的前提下尝试。一个视觉语言模型能看懂屏幕、会写代码、能反思失败；如果再给它一块可以长期读写的工作区，它在原则上就可以把每一局的教训沉淀下来，并在下一个游戏里复用。这类思路在 Minecraft 等单一世界里已有先例（Voyager、Cradle 等），但它们大多依赖结构化的游戏接口，并且没有在不同的游戏之间、用从零开始的对照组测量过迁移。

本报告用一个刻意保持简单、通用的 agent 来回答一个问题：按上面三条标准，我们今天离终身游戏 agent 还有多远？我们的贡献是：

  1. 一套零逐游戏工程的评测方案，包括单游戏学习、跨游戏序列、相似度阶梯和借自持续学习的"链式性能矩阵"，均以从零开始的 agent 作配对对照。
  2. 六条实证发现，分别对应上面三条标准，并给出每条结论背后的机制证据（agent 写下的代码和笔记）。
  3. 对缺口的定位：经验的有效范围止于"画面不变"，原因是 agent 的经验以像素为坐标。

2环境与度量

我们使用 GameWorld 浏览器游戏集。agent 每一步只能看到一张屏幕截图，从游戏注册的几个按键动作中选择一个；推理期间游戏暂停，所以模型思考的快慢不会影响游戏。每局 400 步，每个动作持续 0.1 到 0.2 秒。我们从中选出 10 个可以稳定打分、玩法各异的游戏，按玩法分成四类：

任务完成度。每个游戏有一个任务目标，GameWorld 从游戏内部状态计算完成度，取值 0 到 1，1 表示达成目标。agent 看不到这个数，只能看到屏幕上的分数。随机按键的完成度并不低：在全部可打分的任务上平均为 0.40，所以本报告的数字都应与随机水平对照阅读。

隐藏种子。学习时使用一组随机种子，最终成绩在 agent 从未见过的另一组种子上测量，测量期间不允许学习。

环境修补。我们发现 GameWorld 的 165 个任务中有 31 个所引用的评分字段游戏从不输出，任何策略都得 0 分；我们将这些字段映射到游戏实际输出的等价字段，并在每次运行中记录修补内容。

3Agent：一个给自己写程序的玩家

agent 的全部状态是一个目录，由它自己读写，人不介入。目录里有四样东西：跨游戏笔记、单游戏笔记、一个任何游戏都可以导入的共享代码库，以及每个游戏的技能程序的历次版本和对应的成绩簿。

三个设计约束贯穿全文。第一，反馈只有人类也能看到的东西：屏幕上的分数和死亡，评测用的任务完成度对 agent 不可见。第二，零逐游戏工程：所有游戏使用完全相同的提示词。第三，不规定记忆的内容：我们可以改变反思的时机、可见的信息、存储的上限，但不告诉 agent 应该记什么；如果它没有自发总结出游戏规律，这本身就是一个结果。

为了比较，我们还运行了几种对照：随机按键；无记忆（每局都是新手，模型逐帧决策）；文字记忆的两种形式（把所有历史局塞进上下文，或每局重写一份压缩笔记）；以及代码记忆的两种形式（上述固定结构，和只约定一个入口程序 play.py、其余结构完全由 agent 自定的版本）。

4结果

我们按三条标准的顺序报告六条发现：前两条关于"在一个游戏里变好"和"自组织记忆"，后四条关于"把经验带走"。

4.1在单个游戏里，只有写成代码的经验才产生改进

在只玩一个游戏、每个游戏 10 局的条件下，两种文字记忆与无记忆、随机按键几乎没有区别；两种代码记忆则把完成度提高到 0.53 和 0.61，此时 83% 到 92% 的步数由 agent 自己写的程序决定。把程序拿掉，成绩回到起点。

原因不难理解。时机类游戏的知识是"障碍离我多远、移动多快、什么时候按键"，这种知识只有写成每帧执行的程序才用得上；写在笔记里，模型每一步仍需要 1 秒去看图，节奏早已错过。唯一的例外印证了这一点：在 Wolf3D 中，压缩笔记达到 0.83，因为这个游戏靠找敌人、找门和探索，属于决策而非反应，文字可以承载。

下面是 agent 为 Chrome Dino 写的技能的核心片段，它在之后 5 局 400 步里没有调用一次模型，每局成本约 2 美分：

# agent 自己写的 Chrome Dino 技能（节选，共 131 行）
gray = _gray(frame)
dark = gray < 118                      # 暗像素 = 恐龙、仙人掌、地面
ground = _ground_row(dark, W, H)         # 找地面线
...
d = prev - obs_l                         # 障碍两帧之间移动的距离 = 速度
spd = d if spd is None else 0.6 * spd + 0.4 * d
dist = obs_l - dino[1]
thr = 2.2 * spd                          # 提前量与速度成正比
if dist <= thr:
    return "jump"

这段代码同时包含了两种知识：一个与画面绑死的阈值（红色，"灰度低于 118 的像素就是物体"），和一条与画面无关的游戏规律（蓝色，"起跳提前量与速度成正比"）。4.4 和 4.5 将说明，正是这两者混在一起，决定了经验能走多远。

4.2不给记忆结构，agent 会自己建出单游戏学习所需的结构

我们让 14 个 agent 在只约定入口程序 play.py 的条件下运行，不提供任何笔记、代码库或成绩簿的结构。它们全部自建了笔记，13 个改写自己的程序让它在游戏中写运行日志供下一次反思阅读，8 个建了成绩账本。其中"程序自写日志"是我们设计的固定结构里没有的。它们的成绩不低于固定结构（0.61 对 0.53）。

没有出现的东西同样重要：没有 agent 建立可在游戏之间复用的规律库，也没有建地图或待验证的假设列表。在单个游戏的范围内，模型已经能自己完成"记录、评估、回滚"这一套工程闭环；跨游戏的载体则需要另一种压力或另一种能力。

4.3跨游戏收益是常数，同类游戏的经验没有额外好处

我们让 agent 连续玩 6 个游戏，与在同一游戏上从零开始的 agent 配对比较。用学习效率比 TS(N) 衡量：第 N 个游戏上，有经验 agent 的 10 局平均完成度除以从零开始的 agent。若 agent 在越学越快，TS(N) 应随 N 上升。

有经验确实略好，但这个优势在第 2 个游戏和第 6 个游戏上一样大，并不累积。更出乎意料的是，同类游戏的经验没有带来额外好处：在固定结构下，之前只玩过同类游戏的 agent 比从零开始低 0.12；第 1 局的完成度也更低（0.33 对 0.42）。我们还试了三种只改机制、不规定内容的办法：让 agent 在新游戏第 1 局同时运行"继承版"和"从零版"技能并看到两者的分数；对记忆总量设上限迫使它取舍；以及完全放开结构。三者都没有改变这一结果。

4.4原因之一：它跨游戏记住的几乎都是工程经验

图 4(a) 给出了直接原因。66 条跨游戏要点中，约 40 条是调试和工程方法，约 21 条是图像处理工具，只有 5 条是游戏规律。下面是一个 agent 跨游戏笔记中的三条（原文为英文，此处为译文）：

"一次只改一个变量；保持已验证的路径不变；变差就回滚。"
"语法或导入错误会让整个技能失效：'技能决策 0%' 是红灯。"
"在滚动游戏里，固定宽度的物体停留在危险区的步数等于宽度除以速度。"

前两条是让 agent 在任何游戏里更快排除故障的经验，它确实带到了下一个游戏，这大概就是 TS 中位数 1.27 的来源；这类经验在一两个游戏后就攒齐了，所以收益不再增长。第三条是真正的游戏规律，它恰恰也是 Dino 和 Geodash 共享的那条规律，但它只停留在笔记里，从未变成可复用的代码；每到一个新游戏，agent 都重新写一遍 4.1 节里那样的感知加决策程序。

同类游戏反而吃亏的原因也在代码里。agent 在 Dino 上写了一个找地面、找障碍的模块放进共享代码库；到 Geodash 时它直接导入这个模块写出第一版技能，第 1 局由这段代码玩出 0.30，而从零开始的 agent 让模型看图玩出 0.49。继承来的是感知代码，而感知恰恰是两个游戏最不一样的部分。

4.5经验的有效范围止于"画面不变"

如果不同游戏之间差异太大，那么经验在多小的差异内还有用？我们在同一个游戏上构造了一个逐级加大差异的阶梯，比较"把在原版上玩过 10 局的工作区原样搬过来"的有经验 agent 和从零开始的 agent，各玩 6 局：同一游戏换随机种子；改变操作手感（按键持续时间或游戏速度乘以 1.5）；改一条规则（例如 Wolf3D 中敌人血量变为 3 倍）；换皮（截图颜色反转并轮换通道，游戏逻辑不变，同时撤掉文字规则说明）。三个游戏、两个种子，共 87 个 agent。

阶梯给出了一个清晰的分界。在画面不变的三级里，经验让第 1 局平均高 0.01 到 0.13、6 局平均高 0.10 到 0.17，但 6 局之后从零开始的 agent 追了上来，在隐藏种子上有经验的一方不再领先。经验的价值是"起步快几局"，而不是"上限更高"。成绩簿揭示了一个副作用：有经验的 agent 在 108 局里有 81 局切回了"已验证的冠军版本"，从零开始的只有 18 局；经验让它少探索。

画面一变，经验就从有利变为有害：换皮后有经验 agent 的第 1 局只有 0.18，从零开始的是 0.45，6 对中 5 对为负。它的改版理由（译文）写得很清楚，先是"切回冠军版本 v2"，然后是"灰度低于 118 的掩码选中了黑色背景，从不起跳"，到第 3 局才改出能适应两种明暗的掩码。它存下的感知代码和"哪个版本是冠军"的记录，在换皮后同时失效。

唯一扛住变化的是决策类经验。Wolf3D 中敌人血量变为 3 倍后，有经验 agent 的第 1 局仍高出 0.42，因为它记下的是地图、门和清敌路线，规则变了这些仍然有效。另一个现象值得注意：Dino 的规则改为"只有蹲着才得分"后，12 个 agent、72 局中没有一局系统地尝试过蹲下。这个 agent 不会主动探索去发现规则的变化。

把阶梯与 4.3 放在同一张图上（图 7a），经验的价值随差异增大而下降，在"画面改变"这一步就跌到零以下。另一个同类游戏的画面当然也不同，这解释了 4.3 中同类经验为什么没有用。

4.6连续学习一条游戏链：不越学越快，还会遗忘

前五条结果各自测量一个侧面。为了把"终身学习"作为一个整体来看，我们借用持续学习领域的标准做法（Lopez-Paz & Ranzato, 2017）：agent 依次学一条游戏链，每学完一关，就在一份冻结的副本上把整条链的每一关都测一遍，得到一张性能矩阵。我们为每一关加上"学会它花了多少局"作为成本。

上表是一个理想终身学习者应有的样子（数字为示意）：对角线（深色）是学会的水平；右上（浅蓝）是还没学的游戏因为学过前面的而提前变好，即前向迁移；左下（浅红）是学过的游戏后来是否掉分，即遗忘；最后一列的成本应当递减。我们以 0.8 为"学会"的门槛，每关最多学 8 局，每格在隐藏种子上测 2 局，运行了两条链，各两次：链 A 为三个一键时机游戏接一个第一人称射击（Dino → Geodash → Stack → Wolf3D），链 B 为类型交替的 Snake → Wolf3D → Dino → Stack。

矩阵印证了前面的结论，并补上了一块此前看不到的内容。每个游戏能学到"还行"：学习中某一局达到 0.8 后，在隐藏种子上平均只有 0.70，一次达标不等于学会。前向迁移在零附近，学会成本没有随位置下降（未达标按 9 局计；位置与游戏难度在 4 次运行中无法分开）。

新的发现是遗忘，而且机制很具体。Snake 的技能里写着 import vision，当时共享代码库里没有这个模块，技能无法启动，于是由模型看图来玩，成绩 1.00。后来学 Dino 时，agent 为 Dino 新写了一个同名模块 vision.py。Snake 的旧技能从此导入成功并接管了游戏，每局死亡 12 次，成绩跌到 0.33。Snake 的技能一个字没改，是另一个游戏写进共享库的代码把它带坏了。这与 4.4 中"继承的感知代码拖累新游戏"是同一个机制在时间另一侧的表现：共享的是感知代码，而感知代码在游戏之间并不通用。

需要说明的是，同一份代码在同一组种子上，单局完成度也可在 0.56 到 1.00 之间波动（来自游戏计时的不确定性）。每格只测 2 局时，小于约 0.15 的前向迁移和遗忘与噪声不可区分；上述 Snake 的遗忘是确定性的，其余数字应视为方向。

5讨论：还有多远

终身游戏 agent 需要的能力现状证据
凭反馈在一个游戏里越玩越好能，前提是经验写成代码4.1
自己组织记忆能，限于单游戏内的工程闭环4.2
把一个游戏学到稳定的高水平部分：学到约 0.70，表现不稳定4.6
把经验带到下一个游戏常数级收益，不累积4.3
记住与画面无关的游戏规律否，规律只留在笔记里4.4
经验在环境变化后仍然有效仅限画面不变；决策类经验例外4.5
主动探索以发现规则变化否4.5
越学越快否4.3、4.6
学新游戏不忘旧游戏否，共享代码造成遗忘4.6

三条标准中，前两条已经可以做到，第三条断在一个明确的位置。agent 的经验以"感知代码加成绩记录"的形式存在，两者都以像素为坐标。这一点解释了全部负面结果：同类游戏迁移为负，因为继承的感知代码首先要被修掉；收益不随经历增长，因为工程经验一两个游戏后就饱和；换皮即失效；学新游戏时改写共享感知代码，又会把旧游戏带坏。

我们离终身游戏 agent 的距离，不在于它学不会，而在于它学会的东西只在它看到的像素里有效。

缺口的形状因此也清楚了：缺的是一层与画面无关的表示（物体、相对位置、速度，以及建立在它们之上的规律），以及在这层表示上做抽象的倾向。Dino 技能里的 thr = 2.2 * spd 和笔记里那条"停留步数等于宽度除以速度"说明，模型能写出这样的规律；Wolf3D 的例外说明，这类知识一旦以与画面无关的形式存在，就能跨过规则变化。问题在于它从未把规律从感知代码中分离出来、单独保存和复用。

与已有工作的关系。近期在 12 个虚幻引擎游戏上的 OmniGameArena 发现，反思学到的技能在原版上的提升不能预测它在留出变体上的表现；其中一个游戏上原版提升最大（+201%）的模型，在全部三个变体上都是负迁移，与我们的换皮结果一致。在规则陌生的文字游戏上，Learn2Play Bench 发现保留完整的行动与反馈记录比把经验总结成规则更有效，并且人类玩家比 agent 尝试更多样的策略、更少重复动作，与我们观察到的"守着冠军版本、不探索"相呼应。在文本环境中，有跨环境迁移证据的记忆机制主要是从成功与失败轨迹中对比蒸馏出子任务级经验（ExpeL、ReasoningBank），以及以下游任务回报训练的记忆整理器（Auto-Dreamer）；以提示词驱动的离线"睡眠整理"目前没有任务迁移的证据。让 agent 改写自身学习流程的工作（如 Hyperagents）显示，学到的学习流程可以加快新领域的起步，但证据仍然有限。据我们所知，尚无工作在像素输入下、以从零开始的对照测量过不同游戏之间的技能迁移。

下一步。链式性能矩阵本身可以作为比较不同 agent 设计的统一尺子：对角线衡量学习能力，右上衡量泛化，左下衡量遗忘，成本列衡量是否越学越快。在把尺子做准（每格更多测量、记录共享代码的版本、以连续达标定义"学会"）之后，可以依次检验三类不规定内容的机制：修改共享代码前先在已学游戏上做回归测试（针对遗忘）；定期把所有游戏的技能和曲线并列，要求 agent 寻找共性（针对迁移）；最后以矩阵指标为目标，让 agent 自己改进自己的学习流程。另外两个变量同样需要检验：更强的基座模型是否会自发分离规律与感知，以及共享结构更深、并会反复出现变体的游戏流，是否能为抽象提供足够的回报。

6局限

  • 样本量小。多数条件每格只有 1 到 2 个 agent，同条件下两个 agent 的成绩可相差一倍。各结论的方向在 5 到 9 个游戏或多数配对上一致，单个数值的可信范围约为 ±0.15 到 ±0.3。
  • 只有一个模型。更强的模型是否会自发抽象游戏规律，是本报告最直接的未检验变量。
  • 经历很短。每个游戏 6 到 10 局，最多连续 6 个游戏；多个任务在 1.0 处封顶，压缩了差异。
  • 游戏范围。仅限可暂停的 2D 和简单 3D 浏览器游戏；实时、多人、长时程的策略游戏不在本报告范围内。
  • 个别实验无信息或证据单薄。Dino 的"只有蹲下才得分"一级两边全为 0；"决策类经验耐变化"只在 Wolf3D 一个游戏上观察到；链式实验只有两条链、各两次运行，且链上位置与游戏难度混杂。

实现细节

  • 每步决策关闭模型的思考模式（约 1.2 秒一步）；局后反思开启中等强度的思考，输出预算 4.8 万 token，若思考耗尽预算导致空回复则降低强度重试。
  • 技能程序在独立子进程中运行，每帧时限 2 秒；出错或超时时本步交给模型。
  • 笔记超出上限时截断；共享代码库不设上限（另有一组实验将全部记忆限制在 8000 字以内，见 4.3）。
  • 操作手感变化在按键执行层实现；改规则通过对游戏源码打补丁生成独立副本；换皮在截图上做颜色变换，不影响游戏逻辑。
  • 链式实验中，学习在某一局达到门槛或第 8 局后停止，且该局之后不再反思，以保证被测量的就是实际取得成绩的版本。
